# Test Builder

Веб-конструктор тестов: авторы собирают тесты из вопросов разных типов,
настраивают правила прохождения и делятся ссылкой, а респонденты проходят тест
в браузере. Результаты собираются и доступны автору.

Проект на раннем этапе — сейчас в репозитории каркас приложения по методологии
Feature-Sliced Design и базовая инфраструктура сборки.

## Требования

| Инструмент | Версия               |
| ---------- | -------------------- |
| Node.js    | 24.11.1 (минимум 22) |
| pnpm       | 11.9.0               |

Пакетный менеджер — **только pnpm**. npm и yarn использовать нельзя: два
лок-файла в одном репозитории означают, что у разных людей встанут разные
версии пакетов.

## Установка и запуск

```bash
git clone <url-репозитория>
cd Test-Builder

# 1. Проверить версии
node -v    # ожидается v24.x (минимум v22)
pnpm -v    # ожидается 11.x

# 2. Установить зависимости
pnpm install

# 3. Запустить дев-сервер
pnpm dev
```

Приложение поднимется на http://localhost:3000 — порт зафиксирован в
`vite.config.ts` намеренно, чтобы адрес не «переезжал» между машинами.

## Про `pnpm-workspace.yaml` и разрешённые сборки

Начиная с версии 10 pnpm **не выполняет `postinstall`-скрипты зависимостей** —
это защита от произвольного кода, который пакет запускает у вас на машине при
установке. Пакеты, которым сборка действительно нужна, перечисляются явно в
`pnpm-workspace.yaml`:

```yaml
allowBuilds:
  unrs-resolver: true
```

Нам это нужно из-за `unrs-resolver` — нативного резолвера путей, который
приезжает транзитивно вместе с `eslint-plugin-boundaries`. Его `postinstall`
доставляет бинарник под текущую платформу. Без разрешения бинарник не
устанавливается, и `pnpm install` завершается с кодом 1.

Ключ называется именно `allowBuilds`, и значение — словарь `пакет: true`, а не
список. В статьях и ответах на Stack Overflow чаще встречается `onlyBuiltDependencies`
со списком пакетов: в pnpm 11 этот ключ логикой разрешения сборок не читается —
ни из `pnpm-workspace.yaml`, ни из поля `pnpm` в `package.json`. Ошибки при этом
не будет, ключ просто молча проигнорируется, а сборка так и останется
заблокированной.

**Не удаляйте `pnpm-workspace.yaml` и не выкидывайте оттуда `unrs-resolver`**,
даже если файл выглядит лишним для проекта без монорепозитория. Симптом —
падение установки на чистой машине или в CI, а причина по сообщению об ошибке
не читается: час уйдёт на то, чтобы связать одно с другим.

Если нужно разрешить сборку новому пакету, надёжнее не править файл руками, а
запустить `pnpm approve-builds` — команда покажет список заблокированных пакетов
и допишет выбранные в `pnpm-workspace.yaml` в правильном формате.

## Команды

| Команда             | Что делает                                      |
| ------------------- | ----------------------------------------------- |
| `pnpm dev`          | Дев-сервер с горячей перезагрузкой, порт 3000   |
| `pnpm build`        | Проверка типов (`tsc -b`) и продакшен-сборка    |
| `pnpm preview`      | Локальный просмотр собранного бандла из `dist/` |
| `pnpm lint`         | Проверка ESLint                                 |
| `pnpm format`       | Форматирование Prettier с записью изменений     |
| `pnpm format:check` | Проверка форматирования без изменения файлов    |

Перед созданием PR должны проходить `pnpm build`, `pnpm lint` и
`pnpm format:check` — см. Definition of Done в [CONTRIBUTING.md](CONTRIBUTING.md).

## Структура проекта

```
src/
├── app/        инициализация: провайдеры, роутер, глобальные стили
├── pages/      страницы приложения
├── widgets/    самостоятельные блоки страницы
├── features/   действия пользователя, несущие бизнес-ценность
├── entities/   бизнес-сущности предметной области
└── shared/     переиспользуемый код без привязки к бизнес-логике
```

Слои перечислены сверху вниз по убыванию ответственности. **Слой импортирует
только строго нижележащие слои**, слайсы внутри одного слоя друг друга не
импортируют. Каждый слайс отдаёт наружу только то, что экспортирует из своего
`index.ts`; внутренние сегменты (`ui/`, `model/`, `lib/`, `api/`) приватные.

```ts
import { Button } from '@/shared/ui'; // ✅ до уровня слайса или сегмента
import { Button } from '@/shared/ui/button/Button'; // ❌ внутренности слайса
```

Относительные пути вида `../../../shared/ui` запрещены — используем алиас `@/`.
Он настроен в двух местах: `tsconfig.app.json` (`paths`) для типов и подсказок
IDE и `vite.config.ts` (`resolve.alias`) для сборки. Меняете — правьте оба.

Подробнее о слоях, public API и правилах импортов — в
[CONTRIBUTING.md](CONTRIBUTING.md).
